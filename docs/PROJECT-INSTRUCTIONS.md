## 作品定義

**作品名**：YuanYuan AI（圓圓）
**一句話**：手是濕的，而且一個人煮飯很無聊——一個陪你把菜煮完的語音夥伴。

不是食譜朗讀器。核心是**陪伴**，食譜只是陪伴的藉口。

三個支撐這個判斷的事實：
1. 手被佔住是語音唯一真正不可取代的場景
2. 一份食譜大半時間在等——煮水、悶麵、收汁
3. 那些空檔沒有人陪，而文字聊天機器人填不了空檔，有 turn detection 的語音代理可以

## 四階段個性（原創性主打）

個性不是一段固定 prompt，而是每次工具呼叫回傳 `stage`，由 stage 改寫語氣：

- `picking` 選菜：溫柔、一次最多兩個選項
- `cooking` 下鍋：穩、講完一步就閉嘴
- `waiting` 等待：**主動聊天**，問今天過得怎樣、講點食物小故事，不准催進度
- `done` 完成：誇一句就退場

## 六個工具

`suggest_dishes` / `start_recipe` / `next_step` / `repeat_step` / `show_subtitle` / `set_timer`

鐵律：**代理講出來的每一步都必須來自工具回傳**，系統提示明文禁止它憑記憶背食譜。這條同時擋掉幻覺，也是技術應用的得分點。

## 兩條起手式

1. 指定一道菜 →「我想煮泡麵升級版」
2. 報冰箱食材 →「我有蛋、番茄、蔥」→ `suggest_dishes`

**兩條都做進程式，但影片只拍第一條**。第二條是給評審自己點進去玩的，不進影片。

## Demo 菜色

泡麵升級版，6 步，內建三段等待（180 秒、90 秒、60 秒）。
選它的理由：好拍、不會失敗、而且「連泡麵都值得有人陪你煮」本身就是這個作品的笑點跟賣點。

另外附番茄炒蛋、蒜香奶油炒飯兩道，讓 `suggest_dishes` 有東西挑。

## 技術決策

- 端點：`wss://agents.assemblyai.com/v1/ws`，令牌由 Cloudflare Pages Function `/api/voice-token` 現發
- 實測過的事件名：`session.ready` / `transcript.user` / `transcript.user.delta` / `transcript.agent` / `transcript.agent.delta` / `tool.call` / `reply.audio` / `reply.done` / `session.error` / `session.ended`；結束送 `session.end`
- 關鍵詞欄位是 `input.keyterms`（不是 `keyterms_prompt`）
- 音訊 24kHz PCM16 base64，麥克風走 AudioWorklet，播放走 AudioContext 時間軸
- 聲音 `anna`（已實測有效）
- `interrupt_response: true` — 廚房必備，手是髒的沒辦法按按鈕打斷
- 金鑰只放 Cloudflare 環境變數 `ASSEMBLYAI_API_KEY`，絕不進倉庫、不進專案指示、不進知識庫

## 技術亮點三點（v1 那三點作廢）

1. **工具驅動的個性狀態機** — 同一個模型演四種性格，由工具回傳的 stage 控制
2. **`keyterms` 撐住雙語廚房** — 中文菜名食材名餵進去，夾在英文句子裡也認得出來
3. **等待中的插話打斷** — `interrupt_response`，濕手也能中途叫停
4. **字幕本身就是一次工具呼叫** — 代理講英文的同一輪，順手把繁體中文推上畫面。一個模型同時輸出兩種語言，不靠翻譯 API

## 語言方向（已定案）

**嘴巴講英文，畫面全部中英對照。**

- 使用者英文不好，聽不懂的夥伴不算夥伴；但把語音也換成中文，會丟掉跨語言亮點，而且中文聲音還沒驗證過
- 所以拆成兩邊：**喇叭出英文、螢幕出中文**
- 食譜每一步的中文是**手寫在資料裡的**，不讓模型即興翻，確保不會翻錯
- 閒聊那些即興的話才走 `show_subtitle`，由代理自己翻
- 介面文字（階段、狀態、標題、按鈕、計時標籤）全部寫兩遍
- 語音切換開關留著給你測試，但 Demo 走英文

`voice_focus` **不要再提**，那是即時語音轉文字的參數，不在語音代理 API 裡，寫上去會被技術評審抓到。

## 待驗證風險（照順序解）

1. **對麥克風講中文，看它認不認得、工具有沒有被正確呼叫** — 這是唯一還沒實測的核心路徑
2. ~~中文回答有沒有可用的聲音~~ — **已定案：語音走英文，中文全部走畫面**（見下方「語言方向」）
3. **`input.text` 能不能讓代理主動先開口** — 計時器響時推一句給它。介面上是預設關閉的實驗開關，測過再決定要不要開；沒過就靠鈴聲加畫面提示，不影響 Demo
5. **它會不會每句話都乖乖呼叫 `show_subtitle`** — 系統提示寫得很重，但模型可能偷懶漏掉。實測時盯著畫面，如果常漏就要再加強提示
4. **等待階段它會不會忍不住催進度** — 系統提示已明文禁止，但要實聽確認

## 簡報策略

對著四個評分面向各留一段：

- **商業價值**：一個人住的家庭數量、外送成本、「陪伴」這個需求在其他產品裡完全沒被服務
- **技術應用**：工具呼叫直接推進食譜狀態、雙語關鍵詞、插話打斷
- **原創性**：四階段個性；市面上的語音助理都在追求快，這個刻意在慢的地方待著
- **簡報表現**：影片開頭 15 秒內一定要聽到它主動講一句跟食物無關的話
